## 项目

### 跨境卡审诊断 Agent（已上线）

跨境广告主资质被驳回后，大多数单子要排队咨询值班号。我把值班号的历史答复整理成判例库，同类单子参照判例直接处理。用 Dify 编排工作流：LLM 只负责把反馈抽成结构化字段，检索用"向量 + 关键词"混合召回再 rerank，是否命中、怎么处理由代码判断，这样结果可以复现。

主指标是正确免咨询结案率，只统计没咨询而且判对了的单子，同时用准确率做护栏，防止判错导致二次驳回。上线后这个指标从约 10% 提升到约 40%，单次处理时长从约 200 分钟降到约 100 分钟，每月大约节省 500 小时。反复走特批的判例我整理成规则修改建议，上会 4 次，提了 22 条，采纳 14 条。

### 谱刻 Noto：把歌曲转成可编辑的多轨 MIDI

输入一首混好的 MP3，输出按钢琴、贝斯、鼓分轨的 MIDI，给扒谱和重新编曲的人当起点。我没有从零训练模型，而是按乐器挑现成模型组合，每次替换都对同一份参考逐轨算 F1，确实变好了才采用。

六类乐器实测下来，吉他和弦乐的 F1 都低于 10%，所以 MVP 只承诺钢琴、贝斯、鼓三轨。钢琴路线在 5 首 MAESTRO 真实录音上全部优于基线。评测过程中还发现 Slakh 数据集的贝斯标注高了一个八度。每个版本先冻结，再交给另一个 Agent 只读复核，目前有 139 项自动化测试和 17 个版本标签。

### Codex 用量环

在 Codex 桌面端的侧边栏显示 5 小时和每周剩余额度，并用颜色区分项目、标出会话的 Token 用量。项目基于开源的 [jaykinhoo9/codex-usage-badge](https://github.com/jaykinhoo9/codex-usage-badge)（MIT 许可）。我在 macOS 上加了固定启动入口，把启动、窗口连接、额度读取拆成可以分别检查的步骤；用量环不显示时，能看出卡在哪一步。
